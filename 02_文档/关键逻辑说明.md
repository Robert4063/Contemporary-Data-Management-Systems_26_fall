# 后端关键逻辑说明

本文提供校验、跳转、提交和统计的执行细节及设计理由，属于实现文档。[项目完成报告](../04_项目完成报告/2026_ECNU_PJ1_1_杨家辉.pdf)概述这些方案并分析完成情况，两者独立保留。

## 模块和数据流

后端目录为backend/app/，入口main.py。请求经过FastAPI模型/依赖检查、权限与业务校验，再由PyMongo访问MongoDB，最后返回JSON。前端不直接连接MongoDB。

| 模块 | 职责 |
| --- | --- |
| config.py | 从.env读取连接、数据库名、会话期限和服务端密钥 |
| db.py | 创建或更新四个集合的顶层类型校验器，建立唯一、复合和TTL索引 |
| security.py | PBKDF2密码哈希、会话Token哈希、登录状态验证 |
| models.py | 严格请求类型、题目配置、截止格式、跳转目标检查 |
| logic.py | 单题答案校验、条件匹配、从首题重放答题路径 |
| statistics.py | 从responses查询及聚合真实结果 |
| main.py | 路由、所有权、问卷状态、原子更新、提交与异常响应 |

## 启动、认证和权限

应用启动连接MongoDB并ping，初始化集合/索引，关闭时释放客户端。注册用户名转小写，密码以随机盐PBKDF2-HMAC-SHA256保存；登录生成随机不透明Bearer Token。sessions只保存Token的SHA256，不使用JWT。

每个受保护接口通过current_user验证会话存在、尚未过期且用户存在。TTL只清理过期记录，不代替认证。管理接口owned同时按_id与owner_id查询，非所有者无法管理或统计。持链接的登录用户可以访问发布过的问卷；匿名仍要求登录。

## 创建、保存和发布

点击创建后POST /api/surveys/drafts立即用服务器UTC时间记录created_at，建立revision=1的空草稿。初建空草稿可以暂缺deadline；正式配置保存、发布、修改截止均要求合法含时区ISO8601，截止不早于created_at且晚于服务器当前时间。创建时间不能由请求改写。

模型先校验题目、选项及规则，再原子匹配草稿状态和revision更新，递增版本，过期页面409。发布前重新校验存储配置，至少一题且截止有效。publish-direct在一个文档更新中保存全部编辑内容并发布；不是先保存后发布两次写入。前端确认取消时不请求发布，服务端不依赖确认框保障权限。

发布后题目、规则、匿名/次数策略冻结；metadata接口允许改标题说明，未手动关闭时允许设置合法未来截止。closed为终态；自然到期只由deadline动态计算，不把status改为expired。revision是并发标记，不是完整历史快照。

## 题目配置与答案校验

models.py检查配置：题目ID唯一、选择题至少两项、选项ID唯一、上下界合理、参数与题型匹配。logic.py的validate_answer读取MongoDB题目中的validation检查真实答案。

| 类型 | 答案检查 |
| --- | --- |
| single | 字符串且是有效选项ID |
| multiple | 有效ID数组、不重复、数量在配置范围 |
| text | 字符串、非空必答、长度在配置范围 |
| number | 严格数字，排除布尔/字符串/非有限值/绝对值超9e15，检查范围及整数要求 |

空字符串、纯空白、空数组和null按空回答处理。必答只作用于实际路径经过的题目；选答未填不保存到answers。非法答案422并返回题目ID与具体原因。

## 配置驱动的跳转

jump_enabled决定规则是否执行；rules保存op、value、target。关闭时即使保留规则也不执行。新配置单选每选项最多一个eq目标；多选、数字每题最多一条；文本不支持。目标只能为后续题或END，不能回跳或指向未知题。

| 操作符 | 含义 |
| --- | --- |
| eq / ne | 相等/不等；保留旧单选规则兼容 |
| contains_any | 所配选项至少一个出现在多选答案 |
| contains_all | 所配选项全部出现在多选答案 |
| contains_none | 所配选项全部未出现在多选答案 |
| gt / gte / lt / lte | 数字大于/大于等于/小于/小于等于 |
| between | 数字位于含两端的区间 |

matches只解释这些通用操作符，不写具体问卷条件。walk每次从首题重算：校验当前答案→取第一条命中规则→跳目标或顺序下一题→直到未回答题或结束。拒绝未知题和实际路径之外夹带的答案，不接受客户端自己提交的path。

例如q1选no跳q3，则必答q2不要求作答；请求额外带q2答案反而拒绝。POST next仅返回合法已答内容、实际path、下一题和完成状态，不写正式答卷。进度计算时，可选题要显式提交null才表示跳过；最终校验允许未提供的选答按空处理。

## 截止后的只读访问

status接口也要求登录。已发布/已关闭问卷返回标题、说明、全部只读题目、选项、限制及can_fill；不泄露答卷或统计。截止/关闭详情200，草稿或不存在404。正常填写配置、next及新的提交调用available，非可填写状态410。

因此“能查看”与“能提交”是两个条件。前端据can_fill决定显示答题控件还是只读内容，并提供返回工作台。已登录Token仍须服务端验证，不以浏览器本地标记代替。

## 最终提交、匿名和并发

提交先验证登录和UUID submission_id。按问卷、账号、UUID生成HMAC submission_key，按答案及anonymous生成payload_hash。已有同键同内容返回原结果200，已有同键不同内容409；这一步可在问卷随后截止后确认原成功，不新增答卷。

新提交重新检查问卷、匿名策略及完整路径，再用MongoDB原子匹配published、revision和未来deadline取得准入。保存responses包含survey_id、survey_revision、answers、path、submitted_at、anonymous及幂等字段；实名另存respondent_id。

禁止重复时保存每问卷每账号的HMAC respondent_key，用部分唯一索引保证并发下每账号一次。允许多次则省略该键，新的UUID可以提交新答卷。同一次UUID重试始终只保存一份。匿名不直接保存用户ID，但服务端仍可关联验证HMAC，不承诺绝对不可追踪。

准入和答卷插入没有跨集合事务，已获准的在途提交可能在关闭后完成。admissions可能因失败尝试而增加，不作为答卷总数；统计只认responses真实记录。

## 统计和异常

整卷统计先count_documents，逐题统计检查answers.题目ID是否存在。单选按值分组，多选unwind后分组，未选项补0。文本返回内容，数字返回内容及$avg，无答案平均null。允许多次时数量是答卷人次，不是自然人去重数。

错误码：401认证失败，404不存在/无权，409版本或提交冲突，410不再接收，422格式/配置/答案错误，503数据库不可用。数据库异常记录服务端日志，对客户端返回通用提示；模型错误不回显密码或令牌。

## 路径解释器的执行步骤

对应[logic.py](../01_代码/backend/app/logic.py)的walk；以下为解释性伪代码，不是另一个实现：

```text
建立题目ID到位置的映射；未知答案键记为错误
从第一题开始：
    把当前题加入path
    若为进度计算且未提供当前题：记录下一题并停止
    根据题目配置校验答案；失败则记题目错误并停止
    非空合法答案加入cleaned
    若启用跳转：取第一条匹配规则的target
    target为END则结束；否则跳向target或顺序下一题
检查已提供的题目是否都在实际path内
返回path、cleaned答案、下一题、完成标志和错误
```

校验先于匹配，避免无效选项或非法数字参与跳转。跳过的必答题没有经过，所以不校验；已经填过但后来被新分支跳过的答案必须撤销，不能夹带。规则关闭时只使用顺序路径；保留规则不等于执行规则。

## 幂等键与账号次数键的区别

submission_key的作用域是“问卷、账号、本次UUID”，解决同次提交丢包重试。respondent_key的作用域是“问卷、账号”，解决不允许多次时换UUID再次提交。两者均用服务端密钥生成HMAC，客户端不能指定结果；只保留其中一个不能同时满足这两个目标。

已有submission_key时先比较payload_hash，同内容返回原ID，不进入新提交；这使已成功但随后关闭的答卷仍能确认原结果。没有成功记录才检查当前可填写性、匿名策略、完整路径和准入条件。不是任何截止后的重试都允许，更不是截止后仍能创建新答卷。

## 统计的聚合过程

对应[statistics.py](../01_代码/backend/app/statistics.py)。先按survey_id筛选，再按answers.题目ID是否存在计算answer_count；单选直接按选项ID分组，多选先unwind再分组。最后按题目options顺序补齐未选项的0计数。文本与数字按提交时间返回实际内容，数字再做$avg，无记录返回null。

因此跳过题和空选答不进入该题的回答数；整卷response_count也不用于充当每一道题的分母。允许重复填写时按答卷人次计算。当前逐题和整卷统计复用同一函数，但多查询之间没有快照事务，不能承诺高并发下所有分项来自同一瞬间。
