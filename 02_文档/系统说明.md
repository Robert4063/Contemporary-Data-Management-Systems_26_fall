# 第一阶段最终系统设计

本文件描述当前第一阶段的系统行为。原始需求和用户最后确认的规则构成实现范围。

本文件属于详细设计文档，说明模块职责、交互流程和设计取舍；[项目完成报告](../04_项目完成报告/项目完成报告.pdf)对这些内容作概述与分析，并记录开发、AI使用、测试和问题解决。报告中的重述不替代本目录的实现细节。

## 实现位置与模块边界

| 实现位置 | 具体职责 | 这样划分的理由 |
| --- | --- | --- |
| [frontend/app.js](../01_代码/frontend/app.js) | 登录恢复、问卷编辑、按题填写、只读详情、发布确认和统计展示 | 处理界面状态与用户反馈；最终权限、时间和答案合法性仍交后端判断 |
| [main.py](../01_代码/backend/app/main.py) | 路由、owned/available状态检查、发布与提交写入 | 把HTTP、权限及数据库操作集中在请求边界 |
| [models.py](../01_代码/backend/app/models.py) | 请求类型、配置上下界、规则数量和目标检查 | 配置错误在写入前统一拒绝，普通保存和直接发布共用模型 |
| [logic.py](../01_代码/backend/app/logic.py) | validate_answer、matches、walk | 解释配置，不依赖HTTP或数据库，方便独立验证和后续扩展 |
| [security.py](../01_代码/backend/app/security.py) | 密码哈希、Token哈希、current_user | 将身份验证与具体问卷业务分离 |
| [db.py](../01_代码/backend/app/db.py) | 集合类型校验与索引初始化 | 唯一约束交由数据库处理，避免并发时只靠先查后写 |
| [statistics.py](../01_代码/backend/app/statistics.py) | 单题计数与聚合 | 整卷与单题接口复用同一计算规则，减少两套结果不一致 |

典型请求流程：编辑器发送完整配置，模型检查结构及规则，owned确认创建者，接口再检查截止、状态和版本，最后原子更新问卷。填写流程读取已发布配置，由walk重放路径；只有最终提交才新增responses。HTTP依赖与模型均在接口函数业务代码执行前处理，不把前端检查作为可信输入。

## 架构

同源原生前端 → FastAPI请求模型与登录依赖 → 业务解释器/PyMongo → MongoDB。同步路由在线程池执行同步数据库调用。四个集合为users、sessions、surveys、responses，业务数据仅存MongoDB；本设备进度与会话令牌是浏览器端缓存。

models.py校验配置与请求类型；logic.py校验答案并重放跳转；statistics.py查询答卷；main.py处理权限、生命周期和原子更新；db.py创建集合校验器与索引。前端不接触MongoDB，后端不信任浏览器验证结果。

## 登录与权限

注册用户名3–32位ASCII字母数字下划线，规范为小写；密码8–128位，随机盐PBKDF2-HMAC-SHA256。会话是随机不透明Bearer令牌，MongoDB仅存SHA256哈希，默认24小时。每次请求检查expires_at，TTL仅后台删除。

页面启动先读取同源localStorage中的令牌并GET me，有效则直达目标页面；旧sessionStorage令牌迁移，共享存储不可用时回退单页。未登录或无效才显示登录，不因问卷截止要求反复登录。storage事件同步登录/退出；请求结果关联发起时的令牌，旧会话迟到结果被忽略。同源指协议、主机和端口均相同，不跨浏览器配置共享。禁用存储回退尚未浏览器实测。

所有管理和统计查询以当前账号owner_id过滤，其他账号统一404。填写者只需有效登录并持已发布链接；没有登录前可读状态接口。匿名是答卷署名选择，不是免登录。

## 生命周期与发布

状态为draft → published → closed；自然到期是deadline判定，不改存储status。closed是终态，不能修改截止或直接重新发布。发布后题目、选项、校验、跳转、匿名与次数策略冻结；问卷标题说明可通过metadata接口修改，未手动关闭时可调整必填截止，延长自然截止问卷恢复接收。

点击创建按钮先建空草稿并记录服务器created_at。正式POST、PUT、修改截止和发布都验证有效含时区ISO8601；截止必须不早于created_at且晚于服务器当前时间。只允许初建空草稿暂缺截止，不接收客户端写created_at；时间统一UTC毫秒精度。

保存草稿携带revision，原子匹配draft和版本后递增。编辑页直接发布将当前完整配置与revision交后端，验证后在一个文档原子更新中保存内容与发布状态，保留ID和创建时间；失败不部分写入。工作台发布重新校验已存配置。两个前端入口均先确认，取消不发发布请求，确认框不取代后端权限与校验。

## 配置、选项与跳转

| 类型 | 校验配置 | 新配置的跳转 |
| --- | --- | --- |
| single | 必答、至少两个选项、有效选项ID | 每选项一个目标；默认顺序，或后续题/END |
| multiple | 必答、有效且不重复的ID数组、min_choices/max_choices | 最多1条；contains_any/all/none |
| text | 必答、min_length/max_length | 不支持跳转 |
| number | 必答、minimum/maximum/integer_only | 最多1条；eq/ne/gt/gte/lt/lte/between |

每份最多200题，每选择题2–100个选项。规则数组物理上限100用于单选及旧格式兼容；多选/数字写入最多1条，不是任意题可配100条。文本最大10000个Python Unicode码点，数字绝对值不超过9×10^15，排除布尔、字符串和非有限值。字段ID为字母开头1–40字符，允许字母数字下划线连字符，禁止点号和$。模型拒绝额外字段、重复ID、纯空白题干/选项和题型不适用的非默认规则。

新题jump_enabled=false；启用才显示并执行跳转，关闭保留合法规则并顺序填写。缺字段的旧请求/文档按rules是否非空推断开关。单选新页面生成互斥eq规则，每选项最多一个eq目标；后端保留eq/ne旧格式兼容。旧多规则已发布文档按首条命中解释，旧草稿需用户选择保留一条后再保存，不能把历史兼容当作新多选/数字多规则功能。

contains_none要求已作答的答案集合与非空比较集合无交集；可选题未答时不触发，包括ne。目标为后续题稳定ID或END，禁止向前、自循环与缺失目标。未命中进入下一题。

选项字母是当前位置显示编号，A…Z后为AA/AB，不保存为ID或内容。删项与上移重新编号，规则、答卷继续关联稳定ID；被引用选项或题目须先解除引用才能删除。编辑、比较条件、实际填写、确认及整卷/单题统计共用编号。目标题目改名只更新下拉显示文字，原选择和输入焦点保留。

## 答案与只读访问

walk从第一题重放，逐题先校验再按已启用规则决定目标。不接受客户端当前题或路径；未知题、路径外答案拒绝，被跳过必答题不校验。未答为缺失/null/空字符串/空数组/纯空白文本；必答拒绝，可选不保存空值。进度请求可选题显式null表示跳过，最终请求允许省略。

先登录再GET status：open可填写；expired、closed、incomplete显示全部只读题干、选项和填写要求，不含答卷、身份、统计或内部计数。status返回200不代表提交许可；获取填写配置、next与新提交都重新检查状态，不可填时410。无效ID、草稿或不存在仍404，不伪造截止。

状态、填写、登录及错误页均可返回根工作台；刷新根路径不会再进入问卷。填写中按服务器时间校准到期检查，动作410也切换只读页；服务器才是最终权限依据，不信任客户端时钟。自然到期不删除设备进度，延长后可恢复。

## 匿名、暂存与重试

默认实名、每账号一次，创建者可发布前允许匿名或多次。匿名答卷不含respondent_id；禁止多次时保存HMAC(APP_SECRET,survey_id:user_id)去重键，允许多次时省略。它是受限假名标识，服务器可验证关联，不承诺对运营者绝对匿名。

填写进度按账号与问卷在本设备暂存7天，可关闭/清除；恢复先后端重放。网络恢复失败保留记录，成功提交与退出清除。有效会话可自动恢复，无须每次手工登录。浏览器缓存不是已提交答卷，不进入统计。

每次填写UUID跨刷新与重试保持；submission_key按问卷、账号和UUID作用域HMAC，payload_hash核对内容。首次201，相同内容同次重试200并返回原ID，换内容409；明确再填生成新UUID，仍受allow_multiple限制。已成功记录在关闭后仍可重试确认，不产生新答卷。

## 并发、统计与边界

账号单次和同次提交由两个部分唯一索引保护。提交先原子匹配发布状态、版本和未来截止取得准入，再插入responses；单机MongoDB不使用跨集合事务。关闭前已准入请求可能完成，admissions有失败空缺，不能当作答卷数。

统计按responses实际记录计算，单选group、多选unwind/group、数字avg，文本数字返回全部内容。保留零票选项，无数字回答均值null；允许重复时按人次。多查询统计没有跨查询快照，海量内容分页及压力验证尚未实现。

错误为401/404/409/410/422/503，详细数据库错误只记服务端。用户内容用textContent渲染，CSP与同源API约束保留；未实施或验证的生产限流、HTTPS、总请求大小限制、备份容灾与其他浏览器见[项目完成报告](../04_项目完成报告/项目完成报告.pdf)。第二阶段可沿用现有模块、revision和schema_version扩展，不重做整个系统。

## 关键设计取舍

| 选择 | 考虑过的方式 | 当前决定与影响 |
| --- | --- | --- |
| 服务端重放路径 | 信任前端传来的当前题或path | 根据数据库配置从首题计算，才能发现夹带跳过题、漏答及伪造路径 |
| 状态详情独立接口 | 截止后所有接口都拒绝 | 登录后允许只读详情，另行阻止填写，解决截止后的页面退出问题 |
| 发布后冻结题目 | 允许直接改题与规则 | 保持已有答案和统计含义；若第二阶段要求改题，应增加版本或迁移策略 |
| 动态判断自然截止 | 到时由定时任务改status | 根据服务器时间比较deadline，避免依赖任务及时执行；手动closed单独处理 |
| 账号次数与提交重试分开 | 只在界面禁用提交按钮 | respondent_key限制账号次数，submission_key识别同次重试；允许多次时仍要幂等 |
