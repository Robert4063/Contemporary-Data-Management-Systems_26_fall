# MongoDB最终Schema与索引

本文提供具体字段、文档结构、索引和一致性取舍，供理解或修改实现使用；[项目完成报告](../04_项目完成报告/2026_ECNU_PJ1_1_杨家辉.pdf)中的数据库部分只概述主要选择与完成情况。可执行初始化逻辑为[db.py](../01_代码/backend/app/db.py)，机器结构为[MongoDBSchema.json](../01_代码/MongoDBSchema.json)。

数据库默认questionnaire_stage1，实际连接以.env为准。集合初始化与类型校验器为backend/app/db.py，机器结构见01_代码/MongoDBSchema.json；请求结构见backend/app/models.py及API说明。业务校验不全部下沉到MongoDB校验器。

## 嵌入与引用

| 集合 | 字段与用途 | 选择理由 |
| --- | --- | --- |
| users | username、password_hash、created_at | 账号独立生命周期，用户名唯一 |
| sessions | user_id、token_hash、expires_at | 引用账号，支持过期与撤销；不存原始令牌 |
| surveys | owner_id、元数据、时间、状态、questions、revision | 引用所有者，题目/选项/规则共同发布，嵌入一次读取 |
| responses | survey_id、answers、path、提交身份及幂等字段 | 答卷增长无界，独立文档避免大数组与16MB限制 |

MongoDB没有自动外键，关联由服务端控制。不存在关系数据库表或问卷框架。第一阶段不提供删除账号/问卷接口，避免新增悬空引用。

## 为何采用文档结构

四种题型有不同校验参数，条件规则还包含不同类型的比较值。将同一问卷的题目、选项、validation和rules嵌入一个文档，可以按问卷一次取得完整配置，并在同一文档更新中检查版本、保存配置或发布。没有把每类题型、每个选项和每条规则机械拆成关系式连接结构；这不是说关系数据库不能实现，而是本课程明确要求MongoDB，且当前主要读写单位就是整份问卷。

嵌入也有边界：用户和会话有独立生命周期，答卷数量不断增长，因此独立成集合并以ObjectId引用。这样不会因新增答卷持续扩大问卷文档。仅为提交重试、并发去重与版本标记保存必要字段，不复制用户资料或把统计作为冗余计数长期维护；统计从真实答卷计算。

## 文档结构

```javascript
// users
{_id:ObjectId("..."),username:"alice",
 password_hash:"pbkdf2_sha256$600000$<salt>$<digest>",created_at:ISODate("...")}
// sessions
{_id:ObjectId("..."),user_id:ObjectId("..."),token_hash:"<SHA256>",expires_at:ISODate("...")}
// surveys
{
 _id:ObjectId("..."),owner_id:ObjectId("..."),schema_version:1,revision:2,
 title:"课程反馈",description:"请按实际情况回答",
 allow_anonymous:true,allow_multiple:false,status:"published",
 created_at:ISODate("..."),updated_at:ISODate("..."),published_at:ISODate("..."),
 deadline:ISODate("2030-12-31T15:59:00Z"),admissions:0,
 questions:[
  {id:"q1",title:"参加过课程吗",type:"single",required:true,
   options:[{id:"yes",label:"是"},{id:"no",label:"否"}],
   validation:{min_choices:0,max_choices:null,min_length:0,max_length:10000,
               minimum:null,maximum:null,integer_only:false},
   jump_enabled:true,rules:[{op:"eq",value:"no",target:"q3"}]},
  {id:"q2",title:"年龄",type:"number",required:true,options:[],
   validation:{min_choices:0,max_choices:null,min_length:0,max_length:10000,
               minimum:0,maximum:120,integer_only:true},jump_enabled:false,rules:[]},
  {id:"q3",title:"建议",type:"text",required:false,options:[],
   validation:{min_choices:0,max_choices:null,min_length:0,max_length:300,
               minimum:null,maximum:null,integer_only:false},jump_enabled:false,rules:[]}
 ]
}
// responses
{
 _id:ObjectId("..."),schema_version:1,survey_id:ObjectId("..."),survey_revision:2,
 anonymous:true,submission_key:"<scoped HMAC>",payload_hash:"<SHA256>",
 respondent_key:"<per survey/account HMAC>", // 仅不允许多次时；实名另有respondent_id
 answers:{q1:"no",q3:"希望增加案例"},path:["q1","q3"],submitted_at:ISODate("...")
}
```

ISODate("...")和ObjectId("...")为结构占位，不能直接当作mongosh导入脚本；合法API请求示例见API.md。

题目ID及选项ID是稳定关联键。显示字母由options当前位置生成，不写入label或用作ID；删除或上移只重排数组。答案只保存实际回答的题目，可选未答不存；path由服务器重放，可能含未回答的可选题，不含跳过题。

## 字段约束与生命周期

created_at由创建按钮请求立即记录，UTC毫秒精度，不可客户端修改。初建未完成草稿deadline可以null；正式保存、直接发布、普通发布及截止修改必须为带时区有效时间，不早于created_at且设置时在未来。手动关闭状态优先，不把缺截止伪造成自然到期。发布时间只在发布时写入。

validation统一外形填默认值，但保存时拒绝与题型不匹配的非默认参数。单选/多选2–100选项、最多200题。多选数量范围、文本长度、数字范围及整数限制作为数据保存；规则目标必须是后续题或END。

jump_enabled为严格布尔值，前端新题false；关闭保留有效rules但不执行。旧数据缺字段按rules是否非空推断。多选和数字最多1条，单选每选项至多1个eq目标；单选旧eq/ne格式兼容，旧发布文档不自动迁移。文本不可启用跳转。schema_version为兼容格式标记，revision为并发控制值，不是完整历史版本。

## 索引清单

| 集合 | 索引 | 属性与目的 |
| --- | --- | --- |
| users | username:1 | unique，防并发重名 |
| sessions | token_hash:1 | unique，按令牌哈希查会话 |
| sessions | expires_at:1 | TTL expireAfterSeconds=0，认证仍检查未来时间 |
| surveys | owner_id:1,created_at:-1 | 自己的问卷倒序分页 |
| responses | survey_id:1,submitted_at:-1 | 按问卷筛选和提交时间排序 |
| responses | survey_id:1,respondent_key:1 | 部分unique，仅字符串键参与，保护每账号一次 |
| responses | survey_id:1,submission_key:1 | 部分unique，仅字符串键参与，保护同次提交 |

各集合另有默认_id索引。无需为每个动态题目单建索引，避免膨胀；统计先按问卷筛选后聚合。

## 身份、重试与兼容

匿名答卷无原始账号ID、会话或IP；禁止多次时存在respondent_key，允许多次时省略该字段。实名有respondent_id。字段省略不等同于null，部分索引仅作用于字符串键。

每次填写UUID生成submission_key（作用域为问卷、账号、UUID），答卷不存原始UUID；payload_hash检查重试内容。相同UUID同内容重试返回原答卷，不增统计；不同内容409。匿名HMAC是服务器可验证关联的假名标识，不承诺抵抗运营者关联。

旧答卷无新增字段仍可读取统计，不重写历史记录。新客户端最终提交必须携带UUID；旧客户端缺字段422。密钥需保持稳定。MongoDB顶层类型防线不代表可绕过服务端直接改数据，备份、认证部署、跨集合事务与完整迁移工具不在已验证范围。

## 字段来源与省略规则

| 字段 | 来源与类型 | 写入或省略条件 |
| --- | --- | --- |
| surveys.owner_id | 当前会话用户的ObjectId | 服务端写入，请求不得指定或覆盖 |
| surveys.created_at | 服务器UTC日期，毫秒精度 | 初次创建写入，后续保存保留 |
| surveys.deadline | 带时区请求归一化为UTC日期 | 仅初建未完成草稿可null，正式保存和发布必填 |
| surveys.questions | Question文档数组 | 题目内嵌options、validation、jump_enabled和rules；发布后冻结 |
| surveys.revision | 整数 | 配置修改时匹配旧值并递增，非完整历史快照 |
| responses.answers | 以题目ID为键的对象 | 仅保存服务器重放得到的有效非空答案 |
| responses.path | 题目ID数组 | 服务器计算，可包含经过但未回答的选答题，不含跳过题 |
| responses.respondent_id | 登录用户ObjectId | 仅实名答卷保存；匿名省略，而非写null |
| responses.respondent_key | 每问卷每账号HMAC字符串 | 仅禁止多次时保存，匿名时也适用 |
| responses.submission_key | 问卷、账号与UUID作用域HMAC | 新答卷保存，用于同次重试的唯一识别 |
| responses.payload_hash | 规范JSON内容的SHA256 | 核对同次重试的answers和anonymous是否一致 |

## 原子性和约束分工

编辑使用带status与revision条件的单文档更新；直接发布把完整配置与published状态放在同一次更新中。最终提交先在surveys原子核对published、revision与未来deadline，再插入responses。两个集合之间没有事务，admissions可能包含未成功插入的尝试，不能用作统计答卷数。

唯一索引是最后的并发防线。两个请求即使同时查不到已有答卷，插入时也只有符合唯一约束的一份成功；捕获DuplicateKeyError后先查是否为同次重试，否则返回账号次数冲突。部分索引只让存在字符串键的文档参与，允许多次或历史缺字段答卷不会因省略键而互相冲突。

数据库校验器只保护核心类型；题型专用范围、跳转图和实际答案约束在[models.py](../01_代码/backend/app/models.py)与[logic.py](../01_代码/backend/app/logic.py)中实施。直接绕过后端写MongoDB不能获得同等业务保证。
