# MongoDB数据库设计

## 1. 两阶段结构变化

第一阶段使用users、sessions、surveys、responses四集合，题目嵌入问卷。第二阶段保留四集合，增加questions与usual_questions，分别提供题目内容历史和用户主动收录。

题目版本便于复用和追溯，问卷快照固定发布内容；答卷独立增长，选项和校验嵌入题目，跳转嵌入问卷。文档结构可以保存不同题型的各自约束，嵌入与引用对应不同生命周期。

## 2. 六个集合

各文档均有_id，ID使用ObjectId，时间使用UTC date。类型约束见[MongoDBSchema.json](../01_代码/MongoDBSchema.json)，索引见[db.py](../01_代码/backend/app/db.py)。

| 集合 | 主要字段 |
| --- | --- |
| users | username、password_hash、created_at |
| sessions | user_id、token_hash、expires_at |
| questions | question_id、question_version、owner_id、content、shared_with、parent、restored_from、created_at |
| usual_questions | owner_id、question_id、question_version、in_library、removed_at、revision、created_at、updated_at |
| surveys | survey_id、survey_version、parent_version、owner_id、title、description、status、deadline、questions、revision、allow_anonymous、allow_multiple、schema_version、created_at、updated_at、published_at、admissions |
| responses | survey_document_id、survey_id、survey_version、survey_revision、answers、path、anonymous、submitted_at、schema_version、submission_key、payload_hash；非匿名有respondent_id，限一次有respondent_key |

### 2.1 题目版本

questions每文档是一个确切版本。content包含title、type、required、options、validation；options每项是{id,label}。parent和restored_from是{question_id,question_version}或null。内容不可变，shared_with是可调整的使用授权。

### 2.2 用户收录

usual_questions.owner_id是收录者，questions.owner_id是作者。每个“用户＋题目ID＋版本”只有一条收录。入库设in_library=true，移除设false并记录removed_at；重新收录清除removed_at。同源分组在页面计算，数据库逐版本存放。

### 2.3 问卷内题目

surveys.questions每项是{id,question_id,question_version,content,jump_enabled,rules}。id为本卷本地题号，content为完整快照，rules每项包含op、value、target。复用同题时，各卷分别配置跳转。

## 3. 三类版本标识

| 标识 | 含义 |
| --- | --- |
| question_id＋question_version | 题目的具体内容版本 |
| survey_id＋survey_version | 问卷的具体版本；每版另有物理_id和链接 |
| revision | 当前文档的编辑修订号 |

草稿保存增加revision，创建下一问卷版本才增加survey_version。同一逻辑问卷可保留多版草稿。responses.survey_document_id指向具体surveys._id，版本字段由后端写入。

## 4. 索引

username、token_hash唯一，会话expires_at设TTL。题目ID/版本、问卷ID/版本、收录者/题目ID/版本分别唯一。questions.shared_with支持授权查询；surveys按作者/时间及嵌入题目版本索引。responses按具体问卷版本/时间查询，账号次数键和提交键分别使用条件唯一索引。

## 5. 旧数据升级

启动时补齐原问卷、题目和答卷的版本字段，保留原_id、链接、题号和答案。旧授权只填充缺失字段；旧收录无明确标志时等待确认。原命名题库留作归档，当前程序使用六集合。原单草稿索引改为问卷版本组合唯一，答卷去重改为按具体问卷版本约束。
