# 第二阶段系统说明

## 1. 架构与模块

沿用Python、FastAPI、PyMongo、MongoDB和原生网页。前端调用资源接口，后端读取配置、检查权限并保存数据。第一阶段的账号、四题型、跳转、校验、发布、匿名和统计继续使用。

| 模块 | 职责 |
| --- | --- |
| accounts.py、security.py | 注册、登录、会话与身份 |
| questions.py、versions.py | 题目内容、版本、历史恢复及旧数据转换 |
| usual.py、question_service.py | 主动收录、移除收录、按用户名授权 |
| surveys.py | 草稿、题目引用与快照、问卷版本及发布 |
| responses.py、survey_stats.py | 填写、提交、具体问卷版本统计 |
| permissions.py、models.py、logic.py | 权限、配置校验、答案校验与跳转 |

## 2. 需求一：保存和复用常用题目

questions独立保存一道题的每个版本。点击“放入题库”后，usual_questions记录收录者及题目ID/版本。选入问卷时固定该版本并嵌入内容快照，同一版本可用于多份问卷。

## 3. 需求二：共享题目

作者在⋯菜单选择单题或多选，输入用户名。后端将接收者加入该版本的shared_with；作者继续可用。接收者可选入自己的问卷，主动点击才收录。原题只有作者可转发，新版本另行授权。

## 4. 需求三：保护旧问卷

修改插入新题目版本，发布卷继续保存原引用和快照。草稿中的题可直接修改，保存只更新本版引用。接收者改写共享题时派生自己的question_id，并记录parent来源。

## 5. 需求四：历史与恢复

同一question_id串联各版，parent记录依据版本。历史页展示内容及来源；恢复复制旧内容生成下一版本，记录restored_from，原版本继续保留。

## 6. 需求五：多版共存

各版本独立选用，可分别进入不同问卷，也可用不同本地题号进入同卷。题旁检测可用版本，选择器逐版显示题干、选项、必答和约束，切换指定题目。

## 7. 需求六：引用查询

按题目ID/版本查询surveys.questions，返回自己的问卷、问卷版本和本地题号；作者另见引用总数。发布内容固定，用户可据此选择目标草稿或另建版本。

## 8. 需求七：单题题库

取消命名题库，每条usual_questions收录一个具体版本，界面按question_id分组。新建、修改、恢复和转发不自动入库。可移除一个收录版本或该题全部收录，旧卷、答卷和他人收录保留。

## 9. 需求八：跨问卷单题统计

只汇总当前用户拥有的问卷，按确切题目版本及本地题号关联答卷。单选、多选给选项次数，文本给内容，数字给均值和频数。不同版本分别统计；同卷重复引用分别计回答，答卷数按_id去重。

## 10. 整卷下一版本

题旁操作先保存当前草稿，再复制全部题目、顺序、本地题号、跳转及设置。沿用survey_id，递增survey_version，parent_version记录来源，新旧草稿分别可编辑。从题库选题创建下一版时保留原题并加入所选题，确切版本已存在则不重复添加。
